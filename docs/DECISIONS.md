- 2026-11-06: режим техработ общий: во время него проходят сисадмин и староста группы 24ДММ-2 (`is_journal_admin`), старосты новых групп закрыты вместе со всеми. При необходимости расширить на этапе 6 («Служебное»).

- 2026-11-06: CLI `supabase db query` обрезает текст ошибки до ~1000 знаков, поэтому SQL-тесты возвращают счётчики и первые 5 провалов; полный список смотрите, сужая набор.
- 2026-11-06: кабинеты 2.0 — новые страницы `app.html` (студент) и `headman.html` (староста), без правки 7000-строчного `index.html`; читают новые таблицы по RLS. Игры, достижения и калькулятор рейтинга остаются в `index.html` (ссылки `index.html#games`, `#achievements`, `#zachetka`).
- 2026-11-06: расписание хранится в `schedule_lessons` (по датам); неделя 1 вычисляется из «Текущая - N учебная неделя» на странице bseu.by и сегодняшней даты по Минску; время пары берётся из таблицы звонков `PAIR_TIMES` (комментарии с занятиями времени не содержат).
- 2026-11-06: ручное обновление расписания — Edge Function `schedule-import` (староста, зам, сисадмин; не чаще раза в 10 минут; не пишет при нераспознанной разметке или если исчезло больше 60% будущих занятий); ночной запуск и уведомления об изменениях — этап 3.
- 2026-11-06: exceljs лежит в `vendor/` (раньше грузился с CDN), чтобы отчёт для деканата работал офлайн и в тестах.
- 2026-11-06: даты семестра — в `schedule_meta` (пишет импорт расписания); `groups.semester_end` этапа 1 — копия, оставлена, пока её пишет `schedule-import`.
- 2026-11-06: справки создаются и закрываются только RPC (`certificate_create`, `certificate_resolve`); `received` — конечный статус, поэтому `none` ничего не открывает; `absences.certificate_id` клиент не пишет.
- 2026-11-06: справки и оценки студент видит только свои (пропуски группы — по-прежнему все, решение этапа 1).
- 2026-11-06: часы для главной (`absence_hours_my`) — текущий календарный месяц по Минску, пороги сравниваются с неуважительными часами, как в 1.x (`renderHomeHours`).
- 2026-11-06: уведомления пишут только security definer триггеры и service_role; легаси-импорт (`created_by is null`) уведомлений о пропусках не шлёт.
- 2026-11-06: константный default G24 у `group_id` старых таблиц снят; группу ставит триггер `fill_group_id` (по `student_id` или единственной active-группе); легаси-путь G24 оставлен только для `tasks` под service_role (`_shared/taskstore.ts`).
- 2026-11-06: значки посещаемости считаются по группам; G24 — по `journal_private` до переключения клиента, новые группы — по таблицам, «актуально на» = вчера по Минску.
- 2026-11-06: пропуски и студенты G24 зеркалируются в `journal_private` statement-триггером; `journal-save` после переключения должна отказывать в записи.
- 2026-11-06: RPC этапа 2 проверяют `app_open()` вдобавок к `group_open()`, чтобы security definer не обходил режим техработ.
- 2026-11-07: очередь Telegram — колонки в `notifications` (`tg_status` pending/sending/sent/skipped/failed); добавлены `tg_claimed_at` (поиск «зависших» > 5 минут) и `tg_error`; строки до миграции — `skipped`.
- 2026-11-07: `dedupe_key` — обычный unique `(user_id, dedupe_key)` (работает с PostgREST `on_conflict`) плюс before-триггер, молча пропускающий повторный insert.
- 2026-11-07: в ключи `deadline:`, `cert-due:`, `semester:` входит дата срока/конца семестра: перенесённый срок напоминает снова, следующий семестр не «залипает».
- 2026-11-07: уведомление о семестре — окно 8–14 и 1–7 дней (а не ровно 14 и 7), чтобы пропущенный запуск cron не терял его.
- 2026-11-07: порог деканата — один раз на уровень и месяц; сразу через оба порога — только «деканат»; уважительные часы и пропуски не текущего месяца не оцениваются.
- 2026-11-07: `deadline_soon` не шлётся отметившим задание выполненным (`homework_done`/`deadline_done`).
- 2026-11-07: `tg_reset_all` не трогает существующую строку `tg_rebind` пользователя без привязки: повтор безопасен и не стирает `old_telegram_id`.
- 2026-11-07: `tg_create_link_code` — любой active-участник; ошибка без членства осталась `no_profile` (её знает `profile.js`).
- 2026-11-07: служебные RPC очереди и `notify_daily` не проверяют `app_open()`; при техработах уведомления копятся в `pending`, отправку решает функция.
- 2026-11-07: старый `journal-reminders` (send-reminders) не трогается миграцией; отключить (`cron.unschedule('journal-reminders')`) в день переключения 24ДММ-2 на кабинет 2.0 и сброса бота.
- 2026-11-07: тестовый prelude удаляет (в откатываемой транзакции) уведомления аккаунтов 1–11, оставшиеся от e2e-прогонов.
- 2026-11-07: ключ дедупликации уведомлений о расписании включает время импорта: ночной импорт после ручного обновления в тот же день тоже уведомляет; повторы одного импорта невозможны, потому что изменения считаются относительно базы.
- 2026-11-07: вебхук бота регистрирует функция `tg-webhook-setup` (x-cron-secret), токен не покидает секреты функции; с рабочего компьютера api.telegram.org недоступен.
- 2026-11-07: `delete` без `where` в функциях базы запрещён PostgREST (pg-safeupdate), SQL-тесты через CLI этого не ловят; такие места ловит сквозной тест через REST (`tests/e2e/telegram.mjs`, сброс привязок).
