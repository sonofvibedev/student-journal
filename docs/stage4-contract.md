# Этап 4: контракт (преподаватели и зашифрованный чат)

Исполнители: база и шифрование (Opus), кабинет преподавателя (Sonnet), интерфейс чата и вставка его в кабинеты старосты и преподавателя (Sonnet). Имена ниже обязательны; отступления исполнитель называет в отчёте.

## Роли и тестовые аккаунты
- Два тестовых преподавателя группы 24ДММ-2: лекций (`base_role = teacher_lecture`) и ПЗ (`teacher_practice`). Реальные преподаватели не вносятся. В тесте их создаёт `tools/test/seed-test.mjs`: логины `teacher-lecture@journal-test.example` и `teacher-practice@journal-test.example` (пароль `TEST_PASSWORD`), active-членство в G24 с принятым согласием, назначения `teacher_assignments`: лектор: («Эконометрика», lecture), («Маркетинг услуг», lecture); практик: («Эконометрика», practice), («Маркетинг услуг», practice). В проде назначает сисадмин (этап 5).
- Преподаватель видит только свои предметы и свой вид занятий (RLS этапа 1: `teaches(group, subject, kind)`).
- Чат: пара «староста или заместитель группы ↔ преподаватель». У каждого из них своя переписка с каждым преподавателем (общего ключа на двоих старост нет). Студенты в чат не входят.

## Кабинет преподавателя (`teacher.html` + `teacher.js`, оболочка Cab, `Cab.start({kind:'teacher'})`)
Макеты: `docs/screens/s07.jpg` (Главная, Новый тест, Результаты теста), `s08.jpg` (Группы, Чат, Занятия), `s09.jpg` (Посещаемость, Оценки, Задания). Вкладки внизу: Главная, Журнал, Тесты, Чат. Тесты в этом этапе заглушка «Тесты появятся в следующем обновлении» (второй волной), плитки тестов на главной скрыты.
- Главная: подпись «Преподаватель, <предметы>», карточка «Сейчас идёт лекция/практическое» (по расписанию предметов преподавателя), «Мои группы» (названия, число студентов, «идёт пара»), «Домашки и дедлайны» → задания, строка «Староста <группа>» со значком замка и числом новых сообщений → чат. Экран «Группы» (`#/groups`): карточка группы: посещаемость, число пропусков за неделю, кнопки «Список», «Написать старосте» (метрика «средний балл тестов» — «—» до тестов).
- Журнал (`#/journal`): сегменты «Занятия | Посещаемость | Оценки».
  - Занятия: выбор «предмет и группа»; занятие сегодня (тема, план: тексты) и список других занятий предмета из `schedule_lessons` (ближайшие и прошедшие) со статусом «тема не указана / готово»; сохранение в `lesson_notes`.
  - Посещаемость: выбор пары (занятия предмета и вида преподавателя из расписания), список группы: «был» ↔ «Н, 2 ч» (внесение пропуска преподавателем: `absences.insert` с `lesson_kind` своего вида), записи старосты: кнопка «Уважительный» (меняет `is_excused` по правилу этапа 1), отмена своих и записей старосты своей дисциплины (удаление), счётчик «Отсутствуют: 3 из 28».
  - Оценки: выбор «предмет и вид отметок» (лекционные для лектора, семинарские для практика), тема отметки, дата, список студентов с отметкой 1–10 или «зачтено/не зачтено» (переключатель режима); сохранение в `grades` (upsert логикой клиента: у студента на тему и дату одна отметка), отметка сразу видна студенту (уведомление `grade` уже есть).
- Задания (`#/tasks`): как у старосты (`headman.js`: форма, фильтр «Все | Мои | От старосты», изменить, отменить): преподаватель вносит домашки и дедлайны по своим предметам (subject из списка его предметов), отменяет свои и старосты по своему предмету.
- Чат: общий модуль (см. ниже), вкладки по группам.

## Чат со сквозным шифрованием

### Криптография (`chat-crypto.js`, браузер, Web Crypto API; тестируется и в Node 24)
- Пара ключей пользователя: ECDH P-256. Публичный ключ (JWK) уходит на сервер; закрытый хранится в IndexedDB браузера как неизвлекаемый `CryptoKey` (после распаковки из резервной копии, или сразу после создания) и только в зашифрованном виде на сервере.
- Резервная копия закрытого ключа: JWK закрытого ключа → AES-GCM-256 с ключом из PBKDF2-SHA256 (не меньше 600 000 итераций, соль 16 байт, iv 12 байт) от «пароля переписки», который пользователь задаёт при первом открытии чата (подсказка: можно тот же, что для входа; пароль входа клиенту недоступен после входа). Формат на сервере: `{ v:1, kdf:'PBKDF2-SHA256', iter, salt, iv, ct }` (base64url).
- Общий ключ переписки: ECDH(мой закрытый, публичный собеседника) → HKDF-SHA256 (соль = id треда, info = `journal-chat-v1`) → AES-GCM-256. Каждое сообщение: случайный iv 12 байт, шифртекст AES-GCM с `additionalData = thread_id | sender_id | sender_key_version | recipient_key_version`; в базу уходят только iv и шифртекст (base64url).
- Отпечаток для сверки: первые 8 символов (две группы по 4, верхний регистр) SHA-256 от канонической строки двух публичных JWK (`x`, `y` в base64url), упорядоченных по `user_id`; у обоих собеседников совпадает.
- API модуля (`window.ChatCrypto`):
  - `ChatCrypto.init(sb, uid)` → `{ state }`, где `state` = `'none'` (ключей нет нигде), `'locked'` (ключи созданы, на этом устройстве закрытого ключа нет: нужен пароль переписки), `'ready'`.
  - `ChatCrypto.setup(password)` создаёт пару, сохраняет закрытый ключ в IndexedDB, вызывает RPC `chat_keys_publish` с публичным ключом и резервной копией; `ChatCrypto.unlock(password)` расшифровывает копию с сервера и сохраняет ключ локально (неверный пароль → исключение `bad_password`); `ChatCrypto.reset(password)` создаёт новую пару с `p_reset=true` (старые сообщения станут нечитаемыми; UI предупреждает).
  - `ChatCrypto.encrypt(thread, plaintext)` где `thread = { id, me:{id}, peer:{id, public_jwk, key_version}, my_key_version }` → `{ iv, ciphertext, sender_key_version, recipient_key_version }`; `ChatCrypto.decrypt(thread, msg)` → строка или `null`, если сообщение зашифровано другой версией ключа или повреждено (UI показывает «Сообщение недоступно: ключ был заменён»); `ChatCrypto.fingerprint(thread)` → `'4F2A 91C7'`.
  - Закрытый ключ наружу из модуля не отдаётся; текст сообщений в логи и в `console` не пишется.

### База (миграция `20261108100000_journal2_teachers_chat.sql`)
- `chat_keys(user_id pk, public_jwk jsonb, key_version int, backup jsonb, created_at, updated_at)`: своя строка читается целиком; чужие открытые ключи только через RPC `chat_peer_key`.
- `chat_threads(id uuid pk, group_id, student_user_id, teacher_user_id, kind 'lecture'|'practice', created_at)`, уникально `(group_id, student_user_id, teacher_user_id)`; читают участники (и сисадмин не читает содержимое, только факт, нужен ли ему вообще: нет).
- `chat_messages(id uuid pk, thread_id, sender_id, sender_key_version, recipient_key_version, iv text, ciphertext text, created_at)`: читают только участники; прямых insert/update/delete у клиента нет.
- `chat_reads(thread_id, user_id, last_read_at)`.
- RPC (security definer, `search_path=''`, права по `auth.uid()`, `app_open()`, `group_open()`):
  - `chat_keys_publish(p_public_jwk jsonb, p_backup jsonb, p_reset boolean default false) returns jsonb {key_version}`: первый вызов создаёт версию 1; повтор без `p_reset` обновляет только резервную копию при том же публичном ключе, иначе ошибка `key_mismatch`; с `p_reset` версия растёт.
  - `chat_peer_key(p_thread uuid) returns jsonb {user_id, public_jwk, key_version}` (только участнику).
  - `chat_thread_open(p_group uuid, p_teacher uuid) returns uuid`: староста или заместитель (active, своя группа) открывает/получает тред с преподавателем, назначенным на эту группу; `chat_thread_open_as_teacher(p_group uuid, p_student_user uuid) returns uuid` не нужен: тред создаёт сторона старосты. `chat_threads_my() returns table(thread_id, group_id, group_name, peer_user_id, peer_name, peer_role, kind, last_message_at, unread int)`: мои треды с именами собеседников (преподаватель: «Староста 24ДММ-2» / «Зам. старосты 24ДММ-2»; староста: «Преподаватель лекций» / «Преподаватель ПЗ»), для старосты также преподаватели группы, с которыми треда ещё нет (`thread_id` null).
  - `chat_send(p_thread uuid, p_iv text, p_ciphertext text, p_sender_kv int, p_recipient_kv int) returns uuid`: участник; версии должны совпадать с текущими у обоих (иначе `key_changed`); размер шифртекста до 8 КБ (`too_long`); не больше 30 сообщений в минуту на пользователя (`rate_limited`); создаёт уведомление `chat` второму участнику с фиксированным текстом («Новое сообщение в чате», подпись «Староста 24ДММ-2» / «Преподаватель», без текста), не чаще одного на тред в 5 минут (`dedupe_key = chat:<thread>:<recipient>:<бакет 5 минут>`).
  - `chat_mark_read(p_thread uuid) returns void`.
- Поведение при смене роли: если пользователь перестал быть старостой/заместителем или преподавателем группы, доступ к треду и его чтение закрываются (RLS проверяет актуальные роли), сообщения остаются зашифрованными в базе.

### Интерфейс чата (`chat-ui.js`, общий модуль для `headman.js` и `teacher.js`)
`ChatUI.mount(el, { sb, ctx, role: 'headman'|'teacher', startThread? })` рисует экран чата по макетам s06 (староста: вкладки «Лекции | ПЗ»), s08 средний (преподаватель: вкладки по группам):
- Если у пользователя нет ключей (`state none`): экран «Защитите переписку»: поле «Пароль переписки» (минимум 8 символов, с подсказкой), кнопка «Создать ключи», предупреждение: «Без этого пароля старые сообщения на новом устройстве не открыть». `locked`: «Введите пароль переписки, чтобы открыть чат на этом устройстве» + «Забыл пароль» (ведёт на сброс с предупреждением, что старая переписка пропадёт).
- Строка шифрования с замком «Сквозное шифрование, ключ 4F2A 91C7» и кнопка «Сверить» (лист с отпечатком крупно и текстом: «Сравните этот отпечаток с собеседником вне журнала, например по телефону»).
- Сообщения: свои справа лаймом, чужие слева, время (по Минску), недоступные старые: «Сообщение недоступно: ключ был заменён»; поле ввода и кнопка отправки >= 44 px; опрос новых сообщений раз в 4 с, пока экран открыт; отметка «прочитано» при показе; быстрые сообщения у преподавателя («Перенос пары», «Другая аудитория», «Новое задание») вставляют заготовку в поле.
- Только у старосты: если треда с преподавателем ещё нет, открывает его (`chat_thread_open`).
- Журнал закрыт или чат недоступен: понятный текст, без падения.
- Текст сообщений не попадает в логи, в localStorage и в URL; расшифрованные тексты живут только в памяти страницы.
