# Слово дня автоматически (word-auto)

Слово дня выбирается само каждую полночь по Минску (21:00 UTC). Видит его только админ; остальным слово
открывается лишь когда они сами закончили игру.

## Что сделано

- `supabase/migrations/20261101150000_word_daily_auto.sql` (аддитивная, идемпотентная):
  `word_daily.source` (`auto`/`manual`, у старых строк `manual`), таблицы `word_pool` и `word_settings`,
  RLS без политик и `revoke all` для anon/authenticated у `word_pool`, `word_settings`, `word_bank`, `word_daily`,
  pg_cron задание `journal-word-auto` (`0 21 * * *`, pg_net + `x-cron-secret` из Vault `cron_secret`).
- `supabase/functions/word-auto` (verify_jwt=false) -- ночной запуск.
- `supabase/functions/_shared/wordpick.ts` -- чистая логика выбора (тесты: `node tools/test-word-auto.js`).
- `supabase/functions/_shared/words.ts` -- пул, автовыбор, ручная установка (общий код для word-auto, word-of-day, word-admin).
- `word-of-day` -- ленивое создание слова, если полночный запуск пропущен; закрыта утечка в тренировке (см. ниже).
- `word-admin` -- действия `pool_list`, `pool_toggle`, `set_setting`, `reroll_daily`; `today` показывает слово и `source`.
- `words.js` -- в окне админ-панели слов (создаётся из JS, `index.html` не менялся): опции, пул с переключателями.

## Как выбирается слово

Пул -- `word_pool`; первый запуск заполняет его из индекса рейтингов (`out/index.json.gz` в бакете `assoc-ranks`),
слова из `word_daily` получают `last_used` = последний день. Выбор: случайное **включённое** слово, которого не было
последние 60 суток (или не было никогда). Если таких нет -- берётся треть (минимум одно) самых давних включённых слов,
у них `last_used` сбрасывается на «61 день назад» и выбор идёт среди них. На день ровно одно слово: вставка
`on conflict (day) do nothing` и перечитывание строки, повторный запуск ничего не меняет.

## Порядок в полночь (word-auto)

1. `rpc finalize_assoc_day(вчера по Минску)` -- итоги прошлого дня. Нет функции в базе (миграция
   `20261101120000_assoc_daily_board.sql` не накатана) или другая ошибка -- шаг пропускается, в журнал уходит только код ошибки.
2. Слово нового дня (`ensureDailyWord`).
3. Опционально (`notify_admin_telegram`) -- слово админу в Telegram.

Шаги независимы, статус каждого -- в ответе (`finalize`, `word`). Слово в ответ и в журнал не попадает.
Ленивое восстановление: первое обращение за днём (`word-of-day` любым действием, `word-admin` `today`) создаёт слово
тем же кодом.

## Секреты и опции

- `CRON_SECRET` -- уже есть в секретах функций и в Vault (`cron_secret`).
- Только для опции `notify_admin_telegram`: `TG_ADMIN_IDS` (telegram_id через запятую), `TELEGRAM_BOT_TOKEN`.
- Опции (`word_settings`, по умолчанию выключены) включаются в админ-панели слов или `word-admin` `set_setting`:
  `notify_admin_telegram`, `allow_reroll` (действие `reroll_daily`: замена слова на сегодня, пока нет ни одной строки
  `word_attempts` с названными словами, подсказками или сдачей; пишет `source='manual'`).

## Деплой

1. Применить миграцию (если `finalize_assoc_day` ещё нет -- сначала `20261101120000_assoc_daily_board.sql`).
2. `supabase functions deploy word-auto --no-verify-jwt`
3. Переразвернуть `word-of-day` и `word-admin` (`supabase functions deploy word-of-day`, `word-admin`).
4. Подставить адрес проекта в `url` миграции, если проект другой.

## Проверка

Под админом (вошли в журнал + токен GitHub с правом записи, он в `localStorage.gh_pat`): «Слово дня» в админ-панели
показывает слово, «(выбрано автоматически)» и пул. Под обычным пользователем / редактором / гостем:

- `word-admin` с обычным токеном или без `ghToken` -- `403 not_admin`; без входа -- `401`;
- `word-of-day` `state` -- в ответе `word: null`, `near: null`, пока `finished` не истинно;
- `train_give` / `train_guess` с id сегодняшнего слова -- `404 not_found`;
- прямой запрос к таблицам `word_pool`, `word_daily`, `word_bank`, `word_settings` через REST с anon/authenticated ключом -- отказ.

## Как дёрнуть word-auto руками

```
curl -X POST https://<project>.supabase.co/functions/v1/word-auto   -H "x-cron-secret: <CRON_SECRET>" -H "Content-Type: application/json" -d "{}"
```
Без/с неверным заголовком -- `403 forbidden`. Повтор в тот же день безопасен.

## Где слово может уйти клиенту

| Место | Что отдаётся | Статус |
|---|---|---|
| `word-of-day` view после `finished` | `word`, `near` (сто ближайших) | оставлено: игрок завершил/сдался -- слово дня открывается |
| `word-of-day` guess/hint | места названных слов, слово-подсказка (никогда не №1) | оставлено, часть игры |
| `train_give`, `train_guess` (solved) | слово и `near` тренировочного слова | оставлено, но id теперь только из тренировки (прошлые дни + `train`); слово сегодняшнего дня отсекается |
| `train` (start) | только `id` и размер словаря | как было |
| `word-admin` | всё | только `isRepoAdmin` |
| Telegram | слово админу | только опция `notify_admin_telegram`, `TG_ADMIN_IDS` |

Было: `trainRanks` брал любую строку `word_bank` по id, и перебором id через `train_give` можно было получить
сегодняшнее слово. Исправлено в `word-of-day`.

## Известные расхождения (не чинились)

- Любое действие в `word-of-day`, даже `state`, заводит строку `word_attempts` (поэтому «ответ» в `reroll_daily` --
  непустые guesses/tries/hints/gave_up).
- Гонка двух одновременных `save()` одного игрока.
- Между проверкой «нет ответов» и записью в `reroll_daily` игрок может успеть ответить.

## Пул и ограничение размера

Рейтинг близости слова считает `tools/assoc/prepare.py` и заливает `upload.py`; без этого слово игре недоступно
(`out/<sha256[:32]>.json.gz`). Поэтому пул -- только слова, для которых файл уже есть (источник -- `tools/assoc/targets.txt`,
148 слов). Чтобы вырос до 200-300 слов, нужно дописать слова в `targets.txt`, запустить `prepare.py` и `upload.py`;
`word-auto` подхватит новые слова из `index.json.gz` при следующем `pool_list`/выборе (`ensurePool`).
Файл `targets.txt` лежит в публичном репозитории; сегодняшнее слово из него не следует.
