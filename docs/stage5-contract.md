# Этап 5: контракт (утилита сисадмина: состояние, ошибки, отчёты, роли, группы, служебное)

Исполнители: база (Opus), Edge Functions (Sonnet), клиент: `monitor.js` и страница `sysadmin.html/js` (Sonnet). Имена обязательны; отступления исполнитель называет в отчёте.

Что уже есть (этапы 1–4): `sysadmin.html/js` с разделами Состояние (счётчики), Логи (журнал действий `audit_log`), Роли (заявки, роли старосты и зама), Группы (пороги), Служебное (сброс привязок Telegram); RPC `sysadmin_*`, `tg_reset_all`, `set_maintenance`, `maintenance_status`; функции `schedule-import`, `schedule-nightly`, `tg-*`, `_shared/notify.ts` (`alertSysadmins`).

## База (миграция `20261109100000_journal2_ops.sql`)
- `client_events(id bigint identity pk, at timestamptz default now(), source text check in ('client','server','health'), kind text check in ('error','perf','ping','alert'), name text, message text, detail text, ms int, ok boolean, ua text, group_id uuid null)`: без идентификаторов пользователей. Читает только сисадмин; вставляет только service_role. Индексы по `(at)` и `(kind, at)`. Ограничения длины: name ≤ 120, message ≤ 300, detail ≤ 1000, ua ≤ 120. Хранение 30 дней (cron `journal-ops-cleanup`, 01:15 UTC).
- `ops_state(key text pk, value jsonb, updated_at)`: только service_role (время последнего алерта и сводки).
- `backups(id uuid pk, at timestamptz default now(), kind text check in ('nightly','manual'), path text, size_bytes bigint, tables jsonb, status text check in ('ok','failed'), error text)`: читает сисадмин, пишет service_role. Закрытое хранилище Storage `backups` (private, без политик: доступ только service_role).
- RPC (security definer, `search_path=''`, только сисадмин, `app_open()` там, где пишется):
  - `ops_summary(p_hours int default 24) returns jsonb`: `{availability_pct, pings, resp_p50_ms, resp_p95_ms (по пингам name='db'), page_p50_ms, page_p95_ms (по perf name='page'), client_errors, server_errors, top_errors:[{name,message,count}] (до 5), imports:[{group_id,name,last_import_at,last_status,last_error,lessons_count}], pending_requests, pending_students, last_alert_at, last_digest_at, backup_last:{at,size_bytes,status}|null, maintenance}`; `p_hours` от 1 до 720.
  - `ops_events(p_source text default null, p_kind text default null, p_hours int default 24, p_limit int default 100, p_before bigint default null) returns setof client_events`: от новых к старым, лимит до 200.
  - `sysadmin_find_user(p_email text) returns uuid` (null, если нет).
  - Преподаватели: `sysadmin_assign_teacher(p_user uuid, p_group uuid, p_role text 'teacher_lecture'|'teacher_practice', p_subjects text[]) returns jsonb {ok}` (создаёт или обновляет active-членство без согласия, заменяет `teacher_assignments` пользователя в группе набором предметов с видом занятий по роли; предмет не пустой, до 20 предметов; студент группы преподавателем стать не может, ошибка `is_student`); `sysadmin_remove_teacher(p_user, p_group) returns jsonb` (членство removed, назначения удалены; доступ к чату закрывается политиками); `sysadmin_teachers(p_group uuid) returns table(user_id, email, role, subjects text[], status)`.
  - Сисадмины: `sysadmin_add_sysadmin(p_user uuid)`, `sysadmin_remove_sysadmin(p_user uuid)` (нельзя себя и нельзя последнего), `sysadmin_list_sysadmins() returns table(user_id, email, created_at)`.
  - Группы: `sysadmin_create_group(p_group jsonb, p_students jsonb) returns jsonb {group_id, code}` (формат как `registration_requests.payload.group` и `.students`; код группы показывается один раз; тот же набор проверок, что у `sysadmin_approve_registration`: ФИО уникальны, форма обучения budget/paid/null; логика группы общая с одобрением заявки, без дублирования кода, если можно), `sysadmin_set_group_status(p_group uuid, p_status text 'active'|'closed')` (closed = только просмотр), `sysadmin_group_subjects(p_group uuid) returns text[]` (distinct предметы из `schedule_lessons`).
  - Все изменения пишутся в `audit_log`.
- pg_cron (как в этапе 3: Vault `cron_secret`, url прода в миграции, тестовая копия подменяет): `journal-health` каждые 5 минут → POST `/functions/v1/health-check`; `journal-ops-report` `0 6 * * *` → `/functions/v1/ops-report` (сводка 09:00 Минск); `journal-backup` `30 0 * * *` → `/functions/v1/backup-run`; `journal-ops-cleanup` (SQL: удалить `client_events` старше 30 дней). Создание заданий идемпотентно.

## Edge Functions (без JWT, проверка своя; секреты: те же, что на этапе 3, плюс `SITE_URL`)
| Функция | Кто вызывает | Что делает |
|---|---|---|
| `client-report` | публично (CORS), лимит по хэшу адреса | `{events:[{kind:'error'|'perf', name, message, detail, ms}]}`, до 10 событий за запрос и до 60 за 10 минут с адреса (таблица `join_attempts`, ключ `client-report`); поля обрезаются; из message и detail вырезаются токены (`Bearer …`, `access_token`, длинные hex/base64-строки), строки запроса из URL; пишет `client_events` с `source='client'`; ответ 204 |
| `health-check` | cron (`x-cron-secret`) | пинг базы (лёгкий запрос, мс) и сайта (`GET SITE_URL/app.html`, только если SITE_URL начинается с https://), пишет `kind='ping'` (`name` 'db' или 'site', `ok`, `ms`); затем проверка порогов: ≥ 20 ошибок браузера за 10 минут или доступность за 30 минут ниже 80% → `alertSysadmins` не чаще раза в час (`ops_state`), пишет `kind='alert'` |
| `ops-report` | cron (`x-cron-secret`) или JWT сисадмина (кнопка «Отправить сводку сейчас») | сводка за сутки (доступность, p95, ошибки браузера и сервера, топ-3 ошибки, сбои импорта, заявки, резервные копии) → `alertSysadmins('Журнал: сводка за сутки', …)` (Telegram и почта), `ops_state.last_digest` |
| `backup-run` | cron или JWT сисадмина (manual) | выгрузка таблиц `groups, students, memberships, teacher_assignments, absences, certificates, grades, tasks, lesson_notes, schedule_meta, consents, notification_prefs` постранично по 1000 строк в JSON (без `chat_*`, `tg_*`, `auth`), gzip (`CompressionStream`), в Storage `backups/<YYYY-MM-DD>/<время>-<kind>.json.gz`, запись в `backups` (размер, число строк по таблицам); при ошибке запись `failed` и алерт; хранить 14 дней (старые файлы и записи удалять) |
| `backup-link` | JWT сисадмина | `{id}` → подписанная ссылка на скачивание на 5 минут (`createSignedUrl`), только для записи из `backups` |
| `tg-status` | JWT сисадмина | `{webhook_url, pending_update_count, last_error, bot_username}`; `{action:'reinstall'}` заново ставит вебхук (логика как у `tg-webhook-setup`) |
| `sysadmin-user` | JWT сисадмина | `{email}` → если пользователь с такой почтой есть, `{user_id, created:false}`; иначе создаёт учётную запись Auth (почта подтверждена) со случайным паролем 16 знаков (без похожих символов) и возвращает `{user_id, created:true, password}` один раз, пароль нигде не пишется; нельзя создавать адреса домена студентов `students.journal-24dmm2.app`; запись в `audit_log` без пароля |
| `_shared/oplog.ts` | помощник | `logServer(name, message, detail?)` пишет `client_events` с `source='server'`, не бросает исключений; вызвать в обработчиках ошибок `schedule-nightly`, `schedule-import`, `tg-dispatch`, `backup-run`, `health-check`, `tg-bot` (верхний catch), `notify-registration` |

## Клиент
- `monitor.js` (все страницы 2.0: app, headman, teacher, join, register, sysadmin): перехват `window.onerror` и `unhandledrejection` (message, стек без адресов вне файла и строки), замер загрузки страницы (`perf`, name 'page', ms), медиана времени ответов Supabase за сеанс (`perf`, name 'api'); не больше 5 одинаковых ошибок за сеанс и 20 событий; отправка пачкой через `navigator.sendBeacon`/`fetch keepalive` на `client-report` при скрытии страницы и по таймеру 30 с; ничего личного (токены, тексты сообщений, адреса с параметрами) не отправляется; страница не должна падать, если мониторинг сломан; отключается флагом `window.J2_NO_MONITOR`.
- `sysadmin.js`: разделы по ТЗ
  - Состояние: переключатель 24 часа / 7 дней; доступность %, время ответа (p50, p95), число ошибок браузера и сервера, топ ошибок, страницы (p95 загрузки), состояние импорта по группам, резервная копия, счётчики заявок; блок «Отчёты о сбоях»: пороги, время последнего алерта и сводки, кнопка «Отправить сводку сейчас».
  - Логи: сегменты «Действия | Ошибки браузера | Ошибки сервера | Замеры» (`audit_log`, `ops_events`), «Показать ещё», понятные подписи.
  - Роли: сегменты «Заявки | Роли групп | Преподаватели | Сисадмины». Преподаватели: по группе список, добавление (почта, вид: лекций или ПЗ, предметы из `sysadmin_group_subjects` и вручную; если учётной записи нет, предложить создать её и показать пароль один раз крупно с кнопкой «Скопировать» и предупреждением), снятие. Сисадмины: список, добавление по почте (должна существовать учётная запись), снятие (кроме себя и последнего).
  - Группы: список с кнопками «Отключить/Включить» (`closed` = только просмотр), «Обновить расписание» (функция `schedule-import`) и статусом импорта, пороги (уже есть); форма «Новая группа» (факультет, форма, курс, номер группы, идентификаторы bseu.by с подсказкой, список студентов вставкой «Фамилия Имя; бюджет/платная» или по одному) → `sysadmin_create_group`, код показать один раз.
  - Служебное: режим технических работ (`set_maintenance`, текущий статус), состояние импорта и бота (`tg-status`, «Переустановить вебхук»), резервные копии (список из `backups`, «Скачать» через `backup-link`, «Создать копию сейчас» через `backup-run`), сброс привязок Telegram (уже есть).
- `join.js`: поле входа принимает и почту (содержит `@` → используется как есть, иначе логин → синтетическая почта), чтобы преподаватели и сисадмины могли войти на `join.html` и попасть в свой кабинет; `J2.loginToEmail` в `j2-core.js` обрабатывает `@` так же.
